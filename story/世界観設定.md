# GAIA SENSATION 世界観・作品設計

作中システム名：**GAIA SENSEWARE**

この文書は、作品の世界観、物語の前提、プレイヤー体験、MVPの境界を決める。
人物固有の話し方や生活習慣は「キャラクター設定」、実際の文章と台詞は「物語台本」を正本とする。
UI、保存、プライバシー、会場運営、テスト条件はこの文書だけを正本とし、台本にはプレイヤーへ見せる文言だけを書く。

---

## 1. この作品は何か

### 作品タイトル

**GAIA SENSATION**

### 作中システム

**GAIA SENSEWARE**

一年後の学園祭へ向けて三人が作り始め、最後の三か月をミズハとアマネが仕上げた、地球の公開データへ触れるWeb作品。
観測値を地図、色、波、音へ変え、記録されていることと、そこから考えたことを分けて表示する。

### ジャンル

人物劇を中心にした、ブラウザ向けインタラクティブ・ノベル。

環境データは教材として網羅するためではなく、三人が「記録にないものをどう扱うか」で対立する舞台として使う。

### 一文で表すなら

一年後の発表へ向けて、画面越しに地球観測作品を作ってきた三人。
発表三か月前、一人が文末をダッシュで終えたメッセージを最後に連絡を絶った。
学園祭で作品を開いたプレイヤーは、本人の記録だけで最終画面を組むか、二人が生成してしまった制作過程まで開示するかを選ぶ。
その選択とは別に届いた現在の連絡を受け、二人は展示を止め、中央入口で本人の言葉を聞くために向かう。

### 中心命題

地球の変化も、いなくなった人の意図も、記録にないことを勝手に事実へ変えない。
それでも、自分の言葉を自分の記録として置ける。
次の人へ渡るのは、その内容ではなく、誰かが書いた、あるいは書かなかったという痕跡である。

### プレイヤーに残したい感触

正解を当てた感触ではない。

- 本人の言葉と、本人らしく見える文章は違う。
- 何も書かないことにも操作の跡は残る。
- 自分が書いた文章は、三か月連絡が途絶えた人の続きではなく、現在のセッションだけに自分の名義で表示される。
- 記録が足りなくても、生活と制作は続く。

最後に残るのは、最後に受信した文、現在の本人の声、中央入口へ運ばれる青りんご、三人が話すために置かれた一時休止の札。

## 2. 誰に、どこで、どのくらい遊んでもらうか

### 想定プレイヤー

- ノベルゲームや人物中心の物語が好きな人
- データや生成技術の扱いに関心がある人
- 専門知識はないが、地図や音へ触れる体験を楽しめる人

地球科学の知識は前提にしない。
SOURCE、DERIVEDなどの英語も、初出時に日本語を併記する。

### 基本のプレイ環境

学園祭の展示ブースに置かれた一台の端末。
椅子へ座り、ヘッドフォンまたは小さなスピーカーで遊ぶ。

公開版は同じ内容を一般のブラウザでも開ける。

### 標準の体験時間

目標は初見で20〜30分。
初見テストの中央値が30分を超える場合は、演出速度ではなく本文を削る。

物語上必要な操作は以下に絞る。

1. START
2. LOCAL SOURCEと観測所データを開く順番
3. GXモードで太古の海へ触れ、生命が環境を変えた長い時間を見る
4. 地図モードのMODE 03で森林と雨を重ねる
5. 抽象モードのMODE 07で波の到着差と、本人の文・生成部分を確認する
6. 地図モードへ戻り、MODE 08で自然、人の暮らし、土地の記憶を切り替える
7. 宇宙モードのMODE 10で、これまでの記録を地球全体から見直す
8. MODE 10で、最終画面の編集方針を選ぶ
9. EPILOGUEで、次へ渡す観測姿勢を最大三件まで選ぶ
10. 選んだ姿勢、または選ばなかった空白を最終演出へ反映する

### 短時間の案内

審査や混雑時は、同じ本編を12〜18分で案内する。
別の筋書きや別の結末は作らない。

- 読み上げ待ちを短くする
- 制作一年を三場面だけ表示する
- 操作待ちが長い場合、次に触る場所を示す
- 選択は自動で決めない

## 3. 舞台

### オンライン大学

三人の大学では、授業の大半をオンラインで受ける。
授業が終わるとブラウザを閉じるため、同じ大学に誰がいるのか見えにくい。

学生同士の学内チャットが、教室外の廊下に近い役割を持つ。

### 惑星の放課後

学生が作ったオンラインサークル。

ある授業のあとに出た「人間は、地球を変える側にだけいるのだろうか」という雑談から始まった。
特定の研究や作品制作を義務にせず、身近な場所で気づいた変化を持ち寄る。

写真、短い文、公開データへのリンク、分からなかったことが同じチャンネルへ置かれる。

三人はここで半年間、顔を見ず、声も聞かずに話した。

### 海沿いの展示場

大学の学園祭が開かれる大きな展示施設。
学生のブース、ステージ、企業展示、飲食スペースが同じ建物に入る。

三人が初めて会った場所であり、一年後にGAIA SENSEWAREを公開する場所。
固有の施設名は出さない。

### 大学の共同作業室

海に近い町にある、小さな対面拠点。
大学のキャンパスというより、予約制の貸し会議室に近い。

長机一つ、椅子三脚、共同ディスプレイ、流し台がある。
サクヤが来なかった日と、二人が公開版を仕上げる夜の舞台。

## 4. 時系列

| 時期 | 出来事 |
|---|---|
| 一年半前 | 三人が「惑星の放課後」で同じスレッドに集まる |
| 一年前 | 学園祭当日に初めて会う。目印は青りんご |
| その日 | 展示を回り、「次は出す側」をやると決める |
| その後九か月 | GAIA SENSEWAREを制作する |
| 発表三か月前 | サクヤが共同作業室へ来ず、連絡が途絶える |
| その後二週間 | 二人が大学、サークル、共通の履修者、必要な窓口を通じて安否確認を依頼する |
| 発表前夜 | 事前に三人が公開へ同意した版を基準に、ミズハとアマネが展示を仕上げる |
| 現在 | 学園祭でプレイヤーがGAIA SENSEWAREを開く |

### サクヤの不在と現在について確定していること

- 共同作業室へ来なかった。
- 学内チャット、大学メール、共有済みの連絡先に反応がなかった。
- 午前二時十四分までは制作データを更新していた。
- 最後の投稿は文末がダッシュで終わり、追加メッセージは届いていない。
- ミズハとアマネは、出展申請で共有した本名と学生番号を知っている。
- 住所と家族の連絡先は知らない。
- 大学は安否確認の依頼を受け付けたが、本人の同意が出るまで結果や所在を二人へ開示しなかった。
- 学園祭当日、サクヤ本人が二人への開示に同意し、大学は本人の安全と中央入口で話したいという希望を二人へ伝える。
- サクヤは既存の学内チャットアカウントから音声で中央入口にいると伝え、十六時に二人が本人を直接確認する。
- サクヤ本人は、最初は連絡できない事情があり、連絡できる状態へ戻ったあとも返事をするのが怖くて遅らせたと話す。
- サクヤは、個人的な事情をミズハとアマネへ直接話す意思を示す。

### 確定させないこと

- 連絡できなかった個人的な事情の詳細。家族、医療、住所などを展示へ公開しない
- 最後の文章へ、追加の文を書くつもりがあったか
- 三人の関係が以前と同じ形へ戻るか
- サクヤが共同制作へ復帰するか

個人的な事情を展示へ公開しないことと、現在の安全、所在、本人が認めた行動を曖昧にすることを混同しない。
二人は事情を推測せず、本人から直接聞くために展示を一時休止する。
安否確認中の二人は可能な範囲で動くが、本人の同意が出るまでは結果を知らされない。

## 5. 三人が公開できる根拠

出展申請前に、三人はFESTIVAL BUILD 1.0の公開内容を確認する。

確認事項は次の五つ。

1. その版へ保存した文章、画像、音、表示名を学園祭で公開してよい。
2. 公開後も、誰が作った記録かを変更しない。
3. 新しい文章を、返事のない人の名義で追加しない。
4. 計算や生成で作った内容は、本人の文章と別に表示する。
5. 公開対象として選定済みの制作チャンネル投稿は、候補生成へ利用できる。

三人全員の公開可が残っている。
公開対象には、画面で使われていない構造と設定も含まれる。
候補生成へ利用できるのは、公開対象として選定済みの制作チャンネル投稿だけとする。
個別メッセージ、授業チャンネル、送信されなかった本文は利用しない。

サクヤ不在後に二人が変更した内容は、FESTIVAL BUILD 1.0へ上書きしない。
POST-BUILD CHANGESとして、変更者と時刻を別に表示する。

これにより、二人はサクヤの同意を推測して公開するのではなく、本人が確認した版を公開できる。

## 6. 物語の構造

### 四つのインタラクティブ表示

- GX：太古から現在までの長い時間に触れ、生命と環境が変わり合った順序を見る
- 地図：場所、観測点、同じ地点にある異なる記録を見る
- 抽象：位置情報を粒子、波、色、到着時間へ変え、変化の仕組みを見る
- 宇宙：地球全体まで視点を引き、離れた場所と長い時間の記録を見直す

四つは別々の見せ場を競う機能ではない。
GXで時間を広げ、地図で場所を確かめ、抽象で変化を読み、宇宙で地球全体から見直す順に使う。

MVPでは各モードの自由閲覧機能を完成させる必要はない。
ただし本編の中で、四つすべてを名前だけでなくプレイヤーの操作として一度は通過させる。

### OPENING｜空席

開始直後、三か月前の共同作業室を見せる。
椅子三脚、紙コップ三つ、10:21の「どこにいる？」、未読通知。

サクヤが来ないことを最初に提示してから、一年前へ戻る。

### PROLOGUE｜青りんご

オンライン大学と「惑星の放課後」を短く説明する。
バジルの写真で三人の見方の違いを見せる。

学園祭の朝、顔を知らない三人が青りんごを目印に初めて会う。
展示を回り、「次は出す側」をやると決める。

### 制作した一年

制作期間を網羅しない。次の四場面で関係を示す。

1. 夜間光の白と排出量の赤をめぐる衝突
2. サクヤが森と雨の説明を短くしすぎ、二日間返信を避ける失敗
3. 年越しの初ハドルと三人の生活音
4. 公開同意と、制作者名を二ミリ直す場面

サクヤは作品の正解をすべて知る人物にしない。
意味を守ろうとして条件を削り、返信を避けて二人を待たせる。
その失敗がMODE 03で再び表示される。

### サクヤ不在と捜索

共同作業室へ来ない。
最後の投稿を開く。
二人は二週間、大学と周囲へ安否確認を依頼する。

安否確認を続けている時点では、原因も現在地も分からない。
二人は、三人が公開へ同意した版だけを基準に作業を再開する。

### GXモード｜太古の海

現在の展示へ戻ったプレイヤーが、最初に触れるインタラクティブ表示。

時間軸を太古の海まで戻し、水面をなぞると光合成を行う小さな生命の点が増える。
その活動で生じた酸素が海や大気を変え、あとから別の生物にも使われたことを、長い時間の変化として見る。

ここで伝えるのは、酸素が後世の生物のために作られたという目的ではない。
生命の活動が環境を変え、変わった環境が別の生命の条件になったという順序である。

独立した長編展示にはせず、物語の入口からMODE 03へ渡す短い操作として使う。

### MODE 03｜地図モード／記録にある範囲

GXモードの太古の海から、現在の森林分布がある地図へ移る。

森林と降水量を重ねる。
同じ場所にあることは見えるが、因果関係はこの画面だけでは決めない。

サクヤが以前「森が雨を呼ぶ」と短くしすぎた失敗と、三人で直した履歴を表示する。
その下に、02:13の作業連絡と02:14の最後の受信文を別々の投稿として表示する。
前の投稿を隠して最後の一文だけを意味深に見せない。

### MODE 07｜抽象モード／本人の文と生成部分

地図の震源と観測点を、距離、波、到着時刻だけの抽象表示へ変える。
地震のP波、S波を使い、起きた時刻、届いた時刻、開いた時刻が違うことを見せる。

本人が送った文はSOURCE、ミズハが生成した続きだけをDERIVEDとして分ける。
生成実行と選定の責任者はミズハと明記する。

アマネは候補を非表示にし、ミズハは表示を戻す。
二人は「本人の文と誤認させたくないこと」と「生成した事実まで隠したくないこと」で衝突する。

この画面では最終判断をさせない。
プレイヤーは二つの情報欄を確認し、MODE 10へ進む。

### INTERLUDE｜十二分の海

公開前夜、二人が海岸へ行く。
終電までの十二分、水と缶コーヒー、切れない青りんご。

作品のテーマを会話で説明しない。
二人が作業へ戻り、本人文を完成させず、既存の学生支援案件へ一度だけ面談希望を預けるための休憩として置く。

### MODE 08｜地図モード／使われていない選択面

抽象表示から地図へ戻り、同じ場所にある自然環境、人の暮らし、土地の記憶を別々に表示する。
観測姿勢面は、三人が以前のテストで作った未使用の試作とする。
画面はアマネ、問いかけはミズハ、未選択で進む操作はサクヤが担当した。
サクヤが不在になる前にエンディングを用意していた形にはしない。

本編へ接続する変更は、不在後のミズハとアマネの名義で残す。
同じ画面で、公開前夜に二人が預けた面談希望の受付控えを確認する。学園祭当日に新しい依頼を送る場面にはしない。

### MODE 10｜宇宙モード／最終画面の編集方針

地図から視点を引き、地球全体の表示へ移る。
GX、MODE 03、07、08で触れた記録を、地球上の別々の場所と時間に置く。

その上で、三人の生活音と、サクヤから最後に受信した文が戻る。

プレイヤーは、本人の記録だけで最終画面を組むか、二人が生成した制作過程も別表示で開示するかを選ぶ。
変更されるのは現在のセッション内の表示だけで、学園祭公開版と次の来場者の初期画面は変わらない。

### EPILOGUE｜観測姿勢 / REFLECTION FIELD

編集方針の選択後、次へ渡す姿勢を選ぶ境界のない全画面へ移る。
固定順の三十六文を6×6で表示し、属性名、分類、色分け、内部重みは表示しない。

選択は最大三件。四件目は追加せず、その場で上限を知らせる。
未選択でも先へ進め、空白を判断の失敗として扱わない。

周回や、前の選択を下位扱いする特別な結末は作らない。
編集方針と観測姿勢を正解、不正解で評価せず、その結果を保ったまま通常のエピローグへ進む。

### CURRENT CONTACT / END

編集方針と観測姿勢の選択とは無関係に、公開前夜の面談希望と当日の本人同意に基づく公式連絡が届く。
本人の現在音声、展示の一時休止、中央入口での物理的な対面を順に描く。

プレイヤーは依頼された一時休止札をSTARTの前へ置き、展示端末の前に残る。
中央入口以後は作品の語りへ視点を切り替え、プレイヤーが私的な会話を追跡、聴取、記録する形にはしない。

三人は数歩の距離を残して話し始める。
個人的事情、和解、共同制作への復帰はここで決めない。

## 7. プレイヤーの選択

### 最初の小さな選択

バジルの場面で、どちらを先に見るか選ぶ。

- 売り場の温度計
- 最寄り観測所

どちらもあとから開ける。
選んだ順番は、MODE 10で再生される最初の二音と、最後の操作履歴へ残る。

### 編集方針の選択｜最終画面に何を残すか

- 本人記録で構成する / SOURCE RECORD：本人が送った文だけを最終画面へ表示
- 生成した制作過程も開示する / DISCLOSE DERIVATION：本人の文と、ミズハが生成した部分を責任者と分類を分けて表示

選択結果は操作記録 / VISITOR TRACEへ残す。
学園祭公開版のファイル、次の来場者の初期表示、他の端末は変更しない。

### 最後の選択｜観測姿勢

三十六文から最大三件を選ぶ。選択IDだけを端末へ保存し、選んだ文や得点を結果画面とE.V.E.S.へ表示しない。

各文は内部だけに規則、中立、分岐の三軸の重みを持つ。合計の単独最大を演出系統とし、最大値が同点なら中立、未選択なら無回答とする。

### 四つの演出結果

| 演出 | 空間の変化 |
|---|---|
| 規則へ収束 | 光が経線へ集まり、カメラと音が規則的に静止する |
| 中立 | 異なる記録を統合せず、重なりと空白のあいだに視点を保つ |
| 分岐 | 光が既存の軌道から外れ、カメラと音が外側へ開く |
| 無回答 | 決めなかった記録を空白のまま残し、演出を最小限にする |

四つに正解順位を付けない。SOURCE RECORD / DISCLOSE DERIVATIONは独立した編集判断として残り、編集方針二種と演出四種の組み合わせになる。

## 8. 記録の分類

### 観測記録 / SOURCE

実際に観測、送信、保存された記録。

例：気温、降水量、地震の到着時刻、サクヤが実際に送った文章。

### その場の観測 / LOCAL SOURCE

現場または個人の端末で測った一点の値。

広域の観測値と同じものとして扱わない。
場所、時刻、測定方法を表示する。

### 計算・解釈 / DERIVED

観測記録から計算、補間、生成したもの。

元の記録、作成方法、作成者、作成時刻を表示する。
本人の文章に似ていても、本人の発話として表示しない。

サクヤの文へ続く生成部分では、判断に必要な情報を最初に表示する。

- サクヤが送った文はSOURCEとして別に表示
- 生成した続きだけをDERIVEDとして表示
- 計算・解釈 / DERIVED
- 公開対象として選定済みの制作チャンネル投稿からローカル生成したこと
- 生成実行と選定の責任者がミズハであること
- 本人が確認していないこと

次の情報は「生成履歴を詳しく見る」の中へ折りたたみ、希望したプレイヤーだけが開く。

- 参照した範囲と、参照対象外にした範囲
- 複数候補から一件を選んだこと
- 使用ツールとモデル名。現稿ではQwen2.5-3B-Instructをローカル実行
- 生成時刻
- 本文を人が編集したか

### 仮定 / SCENARIO

条件を変えて試した未来や状況。

観測済みの未来として表示しない。

### 操作記録 / VISITOR TRACE

プレイヤーが実際に行った操作。

例：どちらを先に開いたか、各表示モードで完了した操作、編集方針、観測姿勢を選んだかどうか。

### 端末保存

STARTには通知、警告、版番号を表示しない。
進行、選択ID、算出演出、E.V.E.S.、音量、既読をこの端末のlocalStorageへ保存する。

保存キーは版番号を含まない安定名を使う。旧データはバックグラウンドで変換し、変換できない値は削除せず無視する。
自由入力、投稿本文、会期中の累積件数、投稿痕跡は保存しない。

### 初見プレイヤーテスト

初見の5〜8人に、進行役の説明を加えず最後まで遊んでもらう。

1. 青い生成部分を、サクヤ本人が送った文章だと思わなかったか。
2. 三十六文の選択に正解属性が表示されていないと理解できたか。
3. 選択をしないことも一つの操作として扱われると説明できるか。

一問目と二問目の誤認は0人を合格条件とする。

同じ場で、体験について次の四問を聞く。

1. 三人のうち、誰を最も人間らしく感じたか。そう思った場面はどこか。
2. 中盤で読むのをやめたくなった箇所はどこか。
3. MODE 10の編集方針で本当に迷ったか。
4. 自分の選択で最終画面が変わったと感じたか。

翌日、覚えている場面を一つだけ答えてもらう。
用語ではなく人物の行動や具体物が挙がることを確認する。

## 10. 画面・音・文章

### 画面

人物の立ち絵とデータ演出を同時に詰め込みすぎない。

- 会話中は人物と生活道具を優先する。
- 操作中はデータと凡例を優先する。
- 選択中は、何を選ぶかと何が変わるかを一画面で読めるようにする。

横スクロールを必須にしない。
表は画面幅に合わせて折り返すか、カード表示へ切り替える。

### 色

- SOURCE：白
- DERIVED：青
- SCENARIO：紫
- LOCAL SOURCE：緑
- VISITOR TRACE：薄い黄

色だけに頼らず、必ず文字ラベルを付ける。

### 音

中心となる音は四系統だけ。

1. アマネの扇風機
2. ミズハが湯を沸かす音
3. サクヤの窓から聞こえる踏切
4. 現在の展示ホール

生活音は悲しい音楽の代わりに使う。
感動場面だから音楽を大きくしない。

### 文章

感情より先に生活を書く。

- 紙コップの茶が冷める。
- 缶コーヒーの水滴を拭く。
- 青りんごを切る道具がない。
- 期限の過ぎた食パンを食べる。
- 制作者名を二ミリ動かす。

悲しさ、優しさ、寂しさを作者が先に説明しない。
物の意味を解説しない。
会話ですべてを理解させない。

## 11. 本編がしないこと

- サクヤの個人的な事情を、展示の答えとして公開しない。
- サクヤの現在の安全、所在、本人が認めた連絡の遅れまで曖昧に戻さない。
- サクヤを未来を予知した人物にしない。
- サクヤを作品の正解をすべて知る人物にしない。
- 生成部分を本人の文章として扱わない。
- 何も書かない選択を失敗扱いしない。
- プレイヤーを第四の制作者にしない。
- 地球環境の問題を一つの標語で解決しない。
- データ画面を網羅型教材にしない。
- 周回しないと物語の意味が分からない構造にしない。
- 実装されていない拡張構想をMVPの完成条件にしない。

## 12. 拡張構想

以下は本編完成後に検討する。
この節の存在は実装義務を意味しない。

### 追加MODE

| MODE | 題材 | 本編との関係 |
|---|---|---|
| 01 | 大気中CO2と気温 | 季節変動と長期変化を分ける |
| 02 | 海流、風、海面水温 | 同じ場所へ届く時間の違いを広げる |
| 04 | 花と送粉者 | 記録された関係と未確認を分ける |
| 05 | 再資源化、焼却、最終処分、不明 | 行き先不明を勝手に配分しない |
| 06 | 夜間光と排出量 | 白と赤の制作場面を操作へ広げる |
| 09 | 再生可能エネルギー | 現在値と仮想条件を分ける |

### 三つのアーカイブ

- A：三人が会うまで
- B：GAIA SENSEWAREを作った一年
- C：データと科学の補足

台本末尾の十三件は、執筆資料および拡張版の候補として保持する。
本編中には入口を置かず、最後まで到達したあとに「制作記録を見る」を開放する。
MVPでは三つの入口だけを表示し、十三件の個別画面を完成条件にしない。

### 実物センサー

接続コードをESP32などへ入力し、温度、湿度、照度をLOCAL SOURCEとして受け取る構想。

本名と正確な住所を求めない。
接続時刻、センサー種別、値、粗い地域だけを扱う。
通信できない場合も本編へ影響させない。

### 先端物理学

超弦理論、M理論、IUT、ストレンジ物質、マルチバース、宇宙検閲、シミュレーション仮説は、拡張版の資料名や試作名としてのみ検討する。

本編の謎を解く鍵にはしない。
一般プレイヤーの理解を前提にしない。
科学上の仮説と物語上の比喩を混同しない。

## 13. データの規則

### 出典

各データには、提供機関、データ名、対象期間、更新日、単位を表示する。

想定する提供元：

- NOAA
- NASA
- JAXA
- 気象庁
- USGS
- GBIF
- GloBI
- UN関連統計

### 保存済みデータ

MVPでは、制作時に確認した保存済みデータを使う。
表示する取得日と対象期間を固定する。

リアルタイム取得に失敗して画面が止まる構造を作らない。

### 欠測と推定

記録がない場所は「記録なし」と表示する。
推定値を表示する場合はDERIVEDとし、元データと方法を確認できるようにする。

値がない場所を、見栄えのために既知の値へ置き換えない。

## 14. 制作判断の優先順位

迷った場合は、次の順番で判断する。

1. 三人の人物劇が初見で理解できるか
2. プレイヤーの編集方針と最後の選択が画面結果へ出るか
3. 誰の記録か誤認しないか
4. 20〜30分で最後まで進めるか
5. 音とデータ演出が人物劇を支えているか
6. 拡張機能を追加できるか

下位の項目のために、上位の項目を壊さない。

# GAIA SENSATION 世界観・作品設計

作中システム名：**GAIA SENSEWARE**

この文書は、作品の世界観、物語の前提、プレイヤー体験、MVPの境界を決める。
人物固有の話し方や生活習慣は「キャラクター設定」、実際の文章と台詞は「物語台本」を正本とする。

---

## 1. この作品は何か

### 作品タイトル

**GAIA SENSATION**

### 作中システム

**GAIA SENSEWARE**

ミズハ、アマネ、サクヤが一年かけて作った、地球の公開データへ触れるWeb作品。
観測値を地図、色、波、音へ変え、記録されていることと、そこから考えたことを分けて表示する。

### ジャンル

人物劇を中心にした、ブラウザ向けインタラクティブ・ノベル。

環境データは教材として網羅するためではなく、三人が「記録にないものをどう扱うか」で対立する舞台として使う。

### 一文で表すなら

一年間、画面越しに地球観測作品を作ってきた三人。
発表三か月前、一人が未完の問いだけを残して連絡を絶った。
学園祭で作品を開いたプレイヤーは、本人が送った文章、二人が作った候補、自分の文章を、誰の記録として残すか選ぶ。

### 中心命題

地球の変化も、いなくなった人の意図も、記録にないことを勝手に事実へ変えない。
それでも、自分が選んだことは自分の記録として次へ渡せる。

### プレイヤーに残したい感触

正解を当てた感触ではない。

- 本人の言葉と、本人らしく見える文章は違う。
- 何も書かないことにも操作の跡は残る。
- 自分が書いた文章は、失踪した人の続きではない。
- 記録が足りなくても、生活と制作は続く。

最後に残るのは、未完の問いかけ、三人の部屋の音、次の来場者を待つ青りんご。

## 2. 誰に、どこで、どのくらい遊んでもらうか

### 想定プレイヤー

- ノベルゲームや人物中心の物語が好きな人
- データや生成技術の扱いに関心がある人
- 専門知識はないが、地図や音へ触れる体験を楽しめる人

地球科学の知識は前提にしない。
SOURCE、DERIVEDなどの英語も、初出時に日本語を併記する。

### 基本のプレイ環境

学園祭の展示ブースに置かれた一台の端末。
椅子へ座り、ヘッドフォンまたは小さなスピーカーで遊ぶ。

公開版は同じ内容を一般のブラウザでも開ける。

### 標準の体験時間

初見で20〜30分。

物語上必要な操作は以下に絞る。

1. START
2. LOCAL SOURCEと観測所データを開く順番
3. MODE 03で森林と雨を重ねる
4. MODE 07で本人の文章と候補文を確認する
5. MODE 08で使われていないVISITOR層を見つける
6. MODE 10で二段階の最終選択をする
7. EPILOGUE / WRITE ACCESSを読む

### 短時間の案内

審査や混雑時は、同じ本編を12〜18分で案内する。
別の筋書きや別の結末は作らない。

- 読み上げ待ちを短くする
- 制作一年を三場面だけ表示する
- 操作待ちが長い場合、次に触る場所を示す
- 選択は自動で決めない

## 3. 舞台

### オンライン大学

三人の大学では、授業の大半をオンラインで受ける。
授業が終わるとブラウザを閉じるため、同じ大学に誰がいるのか見えにくい。

学生同士のSlackが、教室外の廊下に近い役割を持つ。

### 惑星の放課後

学生が作ったオンラインサークル。

ある授業のあとに出た「人間は、地球を変える側にだけいるのだろうか」という雑談から始まった。
特定の研究や作品制作を義務にせず、身近な場所で気づいた変化を持ち寄る。

写真、短い文、公開データへのリンク、分からなかったことが同じチャンネルへ置かれる。

三人はここで半年間、顔を見ず、声も聞かずに話した。

### 海沿いの展示場

大学の学園祭が開かれる大きな展示施設。
学生のブース、ステージ、企業展示、飲食スペースが同じ建物に入る。

三人が初めて会った場所であり、一年後にGAIA SENSEWAREを公開する場所。
固有の施設名は出さない。

### 大学の共同作業室

海に近い町にある、小さな対面拠点。
大学のキャンパスというより、予約制の貸し会議室に近い。

長机一つ、椅子三脚、共同ディスプレイ、流し台がある。
サクヤが来なかった日と、二人が公開版を仕上げる夜の舞台。

## 4. 時系列

| 時期 | 出来事 |
|---|---|
| 一年半前 | 三人が「惑星の放課後」で同じスレッドに集まる |
| 一年前 | 学園祭当日に初めて会う。目印は青りんご |
| その日 | 展示を回り、「次は出す側」をやると決める |
| その後九か月 | GAIA SENSEWAREを制作する |
| 発表三か月前 | サクヤが共同作業室へ来ず、連絡が途絶える |
| その後二週間 | 二人が大学、サークル、共通の履修者、必要な窓口を通じて安否確認を依頼する |
| 発表前夜 | 事前に三人が公開へ同意した版を基準に、ミズハとアマネが展示を仕上げる |
| 現在 | 学園祭でプレイヤーがGAIA SENSEWAREを開く |

### サクヤの不在について確定していること

- 共同作業室へ来なかった。
- Slack、大学メール、共有済みの連絡先に反応がない。
- 午前二時十四分までは制作データを更新していた。
- 最後の投稿は途中で終わっている。
- 大学は安否確認の依頼を受け付けたが、結果や在籍状況を二人へ開示しない。

### 確定させないこと

- 死亡、事故、病気、失踪理由
- 連絡を絶つ意図があったか
- 最後の文章の続き
- WRITE ACCESSの設定と不在の因果関係

原因を明かさないことと、二人が探さないことを混同しない。
二人は可能な範囲で動く。その結果を知らされない。

## 5. 三人が公開できる根拠

出展申請前に、三人はFESTIVAL BUILD 1.0の公開内容を確認する。

確認事項は次の四つ。

1. その版へ保存した文章、画像、音、表示名を学園祭で公開してよい。
2. 公開後も、誰が作った記録かを変更しない。
3. 新しい文章を、返事のない人の名義で追加しない。
4. 計算や生成で作った内容は、本人の文章と別に表示する。

三人全員の公開可が残っている。
公開対象には、画面で使われていない構造と設定も含まれる。

サクヤ不在後に二人が変更した内容は、FESTIVAL BUILD 1.0へ上書きしない。
POST-BUILD CHANGESとして、変更者と時刻を別に表示する。

これにより、二人はサクヤの同意を推測して公開するのではなく、本人が確認した版を公開できる。

## 6. 物語の構造

### OPENING｜空席

開始直後、三か月前の共同作業室を見せる。
椅子三脚、紙コップ三つ、10:21の「どこにいる？」、未読通知。

サクヤが来ないことを最初に提示してから、一年前へ戻る。

### PROLOGUE｜青りんご

オンライン大学と「惑星の放課後」を短く説明する。
バジルの写真で三人の見方の違いを見せる。

学園祭の朝、顔を知らない三人が青りんごを目印に初めて会う。
展示を回り、「次は出す側」をやると決める。

### 制作した一年

一年間を網羅しない。次の四場面で関係を示す。

1. 夜間光の白と排出量の赤をめぐる衝突
2. サクヤが森と雨の説明を短くしすぎ、二日間返信を避ける失敗
3. 年越しの初ハドルと三人の生活音
4. 公開同意と、制作者名を二ミリ直す場面

サクヤは作品の正解をすべて知る人物にしない。
意味を守ろうとして条件を削り、返信を避けて二人を待たせる。
その失敗がMODE 03で再び表示される。

### サクヤ不在と捜索

共同作業室へ来ない。
最後の投稿を開く。
二人は二週間、大学と周囲へ安否確認を依頼する。

原因は分からない。
二人は、三人が公開へ同意した版だけを基準に作業を再開する。

### ORIGIN｜結果から目的を作らない

酸素を、地球史の大きな使命として語らない。

光合成の結果として生じた酸素が、あとから別の生物に使われたことを示す。
現在の役割から、過去の目的を決めないという記録上の規則を覚える。

### MODE 03｜記録にある範囲

森林と降水量を重ねる。
同じ場所にあることは見えるが、因果関係はこの画面だけでは決めない。

サクヤが以前「森が雨を呼ぶ」と短くしすぎた失敗と、三人で直した履歴を表示する。
その下から最後の未完投稿が見つかる。

### MODE 07｜本人の文章と候補文

地震のP波、S波を使い、起きた時刻、届いた時刻、開いた時刻が違うことを見せる。

本人が送った文章と、ミズハが過去の投稿から作った候補文を分ける。
アマネは候補を削除せず、本人の文章から離す。

この画面では最終判断をさせない。
プレイヤーは二つの情報欄を確認し、MODE 10へ進む。

### INTERLUDE｜十二分の海

公開前夜、二人が海岸へ行く。
終電までの十二分、水と缶コーヒー、切れない青りんご。

作品のテーマを会話で説明しない。
二人が作業へ戻るための休憩として置く。

### MODE 08｜使われていない層

自然環境、人の暮らし、土地の記憶を別々に表示する。
更新履歴から、サクヤが失踪の三週間前にVISITOR層を作っていたことだけが分かる。

用途は説明されていない。
STATUSはLOCKED。

ここで入力欄の答えをすべて明かさない。

### MODE 10｜二段階の選択

三人の生活音と未完の問いかけが戻る。

プレイヤーは二種類の判断を分けて行う。

1. サクヤの記録をどう展示するか
2. 自分の記録を残すか

### EPILOGUE｜WRITE ACCESS

二段階の選択後、MODE 08のVISITOR層が開く。

失踪の三週間前、テストで未回答の人が先へ進めなかったため、サクヤが「回答必須」を解除していたことが分かる。
最後の投稿の七秒前に残した遺言ではない。

WRITE ACCESSは、サクヤの続きへ書く権利ではない。
プレイヤーがVISITORとして、自分の記録を別の欄へ置く権利。

周回や、前の選択を下位扱いする特別な結末は作らない。
最終選択を否定せず、その直後に通常のエピローグとして開く。

## 7. プレイヤーの選択

### 最初の小さな選択

バジルの場面で、どちらを先に見るか選ぶ。

- 売り場の温度計 / LOCAL FIRST
- 最寄り観測所 / STATION FIRST

どちらもあとから開ける。
選んだ順番は、MODE 10で再生される最初の二音と、最後の操作履歴へ残る。

### 最終選択1｜展示方法

- SOURCE ONLY：本人が送った文章だけを本文へ表示
- SOURCE + DERIVED：本人の文章と候補文を、作者と分類を分けて表示

### 最終選択2｜自分の投稿

- WRITE：次の画面でVISITOR POSTの入力欄を開く
- LEAVE EMPTY：文章を送らず、操作記録だけを残す

### 四つの表示結果

| 展示方法 | 自分の投稿 | 最終画面に残るもの |
|---|---|---|
| SOURCE ONLY | LEAVE EMPTY | 本人の未完投稿、VISITOR TRACE |
| SOURCE + DERIVED | LEAVE EMPTY | 本人の未完投稿、別表示の候補、VISITOR TRACE |
| SOURCE ONLY | WRITE | 本人の未完投稿、VISITOR POST |
| SOURCE + DERIVED | WRITE | 本人の未完投稿、別表示の候補、VISITOR POST |

四つに正解順位を付けない。
表示されるファイル数とVISITOR POSTの有無は、画面上ではっきり変える。

## 8. 記録の分類

### 観測記録 / SOURCE

実際に観測、送信、保存された記録。

例：気温、降水量、地震の到着時刻、サクヤが実際に送った文章。

### その場の観測 / LOCAL SOURCE

現場または個人の端末で測った一点の値。

広域の観測値と同じものとして扱わない。
場所、時刻、測定方法を表示する。

### 計算・解釈 / DERIVED

観測記録から計算、補間、生成したもの。

元の記録、作成方法、作成者、作成時刻を表示する。
本人の文章に似ていても、本人の発話として表示しない。

### 仮定 / SCENARIO

条件を変えて試した未来や状況。

観測済みの未来として表示しない。

### 操作記録 / VISITOR TRACE

プレイヤーが実際に行った操作。

例：どちらを先に開いたか、入力欄を開いたか、文章を送らなかったか。

### 来場者の投稿 / VISITOR POST

プレイヤーが実際に送った文章。

投稿が行われた事実と本文はVISITOR POSTとして扱う。
本文内に仮想の未来条件を書いた場合、その条件部分だけをSCENARIOとして示せる。

VISITOR POST全体をSCENARIOにはしない。

## 9. MVP

### MVPで必須のもの

- CURRENT、OPENING、PROLOGUE
- ORIGIN
- MODE 03、07、08、10
- INTERLUDE「十二分の海」
- 二段階の最終選択
- EPILOGUE / WRITE ACCESS
- 青りんご、空席、紙コップ
- 扇風機、湯、踏切、展示ホールの音
- SOURCE、DERIVED、VISITOR TRACE、VISITOR POSTの表示
- 保存済みローカルデータ
- 途中保存と再開
- 音量調整、音なし、動きを減らす設定

### MVPで実装しないもの

- MODE 01、02、04、05、06、09の独立した体験画面
- 二周目、隠し解除条件、特別な周回エンド
- 十三件の個別アーカイブ画面
- リアルタイムAPI取得
- 実物センサー接続
- 宇宙、地図、抽象を別々の自由閲覧モードとして作ること
- 先端物理学の隠し謎解き
- ユーザー登録、正確な住所、本名の収集

MVP外の項目が未完成でも、本編は欠けた状態に見えないこと。

### 完了条件

| 項目 | 完了条件 |
|---|---|
| 導入 | STARTから5分以内に空席、未読通知、10:21の「どこにいる？」を見る |
| 人物 | 青りんご、白と赤、サクヤの失敗、年越しの音、公開同意を本編内で確認できる |
| 捜索 | 大学、サークル、共通の履修者、必要な窓口への安否確認が描かれる |
| 公開根拠 | FESTIVAL BUILD 1.0へ三人の公開可が表示される |
| 必須画面 | ORIGIN、MODE 03、07、08、10を順に完了できる |
| 分類 | SOURCE、DERIVED、VISITOR TRACE、VISITOR POSTを色だけでなく文字で区別できる |
| 選択 | 二段階の選択から四つの表示結果が生まれる |
| 報酬 | 選択直後にEPILOGUE / WRITE ACCESSが開き、MODE 08で不明だったVISITOR層の用途が分かる |
| 尺 | 初見プレイヤーが20〜30分でEPILOGUEまで到達する |
| 障害時 | 外部通信、音、センサーがなくても最後まで進める |
| 復帰 | 再読み込み後も進行、二つの選択、音量設定を失わない |

### テストで測るもの

- STARTから空席までの時間
- 最初の操作までの時間
- 各必須MODEで止まった時間
- SOURCEとDERIVEDを取り違えた回数
- 選んだ二つの最終選択
- EPILOGUE到達率
- 総プレイ時間

入力本文、本名、住所は測定しない。

## 10. 画面・音・文章

### 画面

人物の立ち絵とデータ演出を同時に詰め込みすぎない。

- 会話中は人物と生活道具を優先する。
- 操作中はデータと凡例を優先する。
- 選択中は、何を選ぶかと何が変わるかを一画面で読めるようにする。

横スクロールを必須にしない。
表は画面幅に合わせて折り返すか、カード表示へ切り替える。

### 色

- SOURCE：白
- DERIVED：青
- SCENARIO：紫
- LOCAL SOURCE：緑
- VISITOR TRACE：薄い黄
- VISITOR POST：黄

色だけに頼らず、必ず文字ラベルを付ける。

### 音

中心となる音は四系統だけ。

1. アマネの扇風機
2. ミズハが湯を沸かす音
3. サクヤの窓から聞こえる踏切
4. 現在の展示ホール

生活音は悲しい音楽の代わりに使う。
感動場面だから音楽を大きくしない。

### 文章

感情より先に生活を書く。

- 紙コップの茶が冷める。
- 缶コーヒーの水滴を拭く。
- 青りんごを切る道具がない。
- 期限の過ぎた食パンを食べる。
- 制作者名を二ミリ動かす。

悲しさ、優しさ、寂しさを作者が先に説明しない。
物の意味を解説しない。
会話ですべてを理解させない。

## 11. 本編がしないこと

- サクヤの不在理由を答え合わせしない。
- サクヤを未来を予知した人物にしない。
- サクヤを作品の正解をすべて知る人物にしない。
- 候補文を本人の文章として扱わない。
- 何も書かない選択を失敗扱いしない。
- プレイヤーを第四の制作者にしない。
- 地球環境の問題を一つの標語で解決しない。
- データ画面を網羅型教材にしない。
- 周回しないと物語の意味が分からない構造にしない。
- 実装されていない拡張構想をMVPの完成条件にしない。

## 12. 拡張構想

以下は本編完成後に検討する。
この節の存在は実装義務を意味しない。

### 追加MODE

| MODE | 題材 | 本編との関係 |
|---|---|---|
| 01 | 大気中CO2と気温 | 季節変動と長期変化を分ける |
| 02 | 海流、風、海面水温 | 同じ場所へ届く時間の違いを広げる |
| 04 | 花と送粉者 | 記録された関係と未確認を分ける |
| 05 | 再資源化、焼却、最終処分、不明 | 行き先不明を勝手に配分しない |
| 06 | 夜間光と排出量 | 白と赤の制作場面を操作へ広げる |
| 09 | 再生可能エネルギー | 現在値と仮想条件を分ける |

### 三つのビュー

- 地図：場所と観測点を見る
- 抽象：変化を粒子、波、色で見る
- 宇宙：地球全体と長い時間を見る

MVPでは独立したモードにせず、必須画面内の演出として必要な範囲だけ使う。

### 三つのアーカイブ

- A：三人が会うまで
- B：GAIA SENSEWAREを作った一年
- C：データと科学の補足

台本末尾の十三件は、執筆資料および拡張版の候補として保持する。
MVPでは三つの入口だけを表示し、個別画面の実装を完成条件にしない。

### 実物センサー

接続コードをESP32などへ入力し、温度、湿度、照度をLOCAL SOURCEとして受け取る構想。

本名と正確な住所を求めない。
接続時刻、センサー種別、値、粗い地域だけを扱う。
通信できない場合も本編へ影響させない。

### 先端物理学

超弦理論、M理論、IUT、ストレンジ物質、マルチバース、宇宙検閲、シミュレーション仮説は、拡張版の資料名や試作名としてのみ検討する。

本編の謎を解く鍵にはしない。
一般プレイヤーの理解を前提にしない。
科学上の仮説と物語上の比喩を混同しない。

## 13. データの規則

### 出典

各データには、提供機関、データ名、対象期間、更新日、単位を表示する。

想定する提供元：

- NOAA
- NASA
- JAXA
- 気象庁
- USGS
- GBIF
- GloBI
- UN関連統計

### 保存済みデータ

MVPでは、制作時に確認した保存済みデータを使う。
表示する取得日と対象期間を固定する。

リアルタイム取得に失敗して画面が止まる構造を作らない。

### 欠測と推定

記録がない場所は「記録なし」と表示する。
推定値を表示する場合はDERIVEDとし、元データと方法を確認できるようにする。

値がない場所を、見栄えのために既知の値へ置き換えない。

## 14. 制作判断の優先順位

迷った場合は、次の順番で判断する。

1. 三人の人物劇が初見で理解できるか
2. プレイヤーの二つの選択が画面結果へ出るか
3. 誰の記録か誤認しないか
4. 20〜30分で最後まで進めるか
5. 音とデータ演出が人物劇を支えているか
6. 拡張機能を追加できるか

下位の項目のために、上位の項目を壊さない。

## 15. 最後に残すもの

未完の問いかけ。

本人が送った文章。
本人らしく見えるが、本人が送っていない文章。
プレイヤーが書いた、プレイヤー自身の文章。

三つを同じ作者へ寄せない。

青りんごの横で次の人がSTARTへ触れたとき、前のプレイヤーの選択は正解としてではなく、誰が何を残したかという記録として続いている。
